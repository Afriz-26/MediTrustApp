## 4. Database facts (live project)
- Tables: profiles(role), doctors, doctor_schedules, appointments(token_no, status), prescriptions, notifications, pharmacies, medicines(source, reviewed, rx_only), pharmacy_inventory(price, mrp NOT NULL, CHECK price <= mrp), reservations, reservation_items(unit_price set at acceptance), subscriptions(plan,starts_at,ends_at,payment_method,payment_ref), subscription_requests, onboarding_leads, lead_requesters, chat_sessions/chat_messages, ai_usage, directory_listings (RLS: signed-in read active; admin write). Views: doctors_public, pharmacies_public, inventory_public(+mrp), v_appointments, v_prescriptions, v_reservations, v_my_requests (security-definer, caller-scoped by design: PROVE with the two-account RLS test).
- Trial/plan logic: triggers grant_trial_doctor / grant_trial_pharmacy (on verification -> approved) create a 'trial' subscription (28 days) while fewer than 10 trials exist and the user has no subscription; else notify "choose a plan". activate_subscription stacks a paid plan after the current end date. pg_cron job `notify-expiring-plans` daily 03:30 UTC sends "Plan ending soon" (3 days) and "Plan ended". A provider is visible to patients only if verified + live subscription + (doctor) fee + schedule (provider_is_live()).
- Notifications are created by DB functions with personal text (names, dates, token MT-003). Client-side notification creates are ignored. Profile guard: an approved doctor/pharmacy who changes credentials (doctor: name, registration no, qualification, speciality; pharmacy: name, owner, licence no) goes back to Pending (hidden) and admins are notified; other edits apply immediately and notify admins.
- Tokens: token_no = order the doctor CONFIRMS (max+1 per doctor per day), NOT appointment-time order; doctors have walk_in_reserve_pct but no UI. Patient is notified "Your token is MT-003".
- Edge Function `ai` v5: signed-in only, 40 requests/user/day (failed attempts count), tries gemini-3.5-flash-lite first, then lists models and tries others if Google says "not found", 15 s per attempt. Secret GEMINI_API_KEY set. Logs: gemini_ok <model> <ms>, gemini_model_not_found, gemini_rate_limited. When the cap is hit the function returns 429 "You have reached today's assistant limit. Please try again tomorrow." shown as a bot message. The adapter retries once on HTTP 503, which can double quota use.
- Security advisors (last run): 7 security-definer views (by design), leaked-password protection off.

## 9. Operations runbook (use WITHOUT AI if needed; Supabase dashboard > SQL Editor)
- Something is broken: (1) Supabase Dashboard > Logs (Edge functions, API, Postgres), (2) open the site with F12 > Console, (3) Netlify > Deploys > "Publish deploy" on the last good one to roll back, (4) switch a feature off in src/config/features.js and redeploy.
- AI chat fails: Edge Functions > ai > Logs. "gemini_model_not_found" is handled automatically; repeated "gemini_rate_limited"/503 = Google busy/free-tier limit -> consider a paid Gemini key (GEMINI_API_KEY secret). Daily cap secret: AI_DAILY_LIMIT.
- Extend or create a provider plan (SQL editor runs as postgres):
  `insert into subscriptions (provider_user_id, plan, starts_at, ends_at, payment_method, payment_ref) values ('<provider user uuid>', 'basic', now(), now() + interval '28 days', 'manual', 'MANUAL-EXTENSION');`
  (find the uuid: `select user_id, display_name from doctors;` or `select user_id, name from pharmacies;`).
- Hide a provider from patients: `update doctors set verification = 'rejected' where id = '<id>';` (or pharmacies). Restore with 'approved' (does NOT grant a new trial if they already have a subscription).
- Trial slots used: `select count(*) from subscriptions where plan = 'trial';`
- Admin check: `select id,email,role from profiles where role='admin';`; password resets via Supabase Auth dashboard.
- Supabase paused (free tier idle 7 days): open the project dashboard and press Restore; set up a keep-alive ping.
- Data safety: weekly CSV export of doctors, pharmacies, appointments, prescriptions, reservations, subscriptions, profiles; upgrade to Supabase Pro ($25/mo) at the first paying provider or first real patient data.
